# Покерный тренер

Ассистент для 6-max No-Limit Hold'em (кэш, 100bb): по раздаче даёт совет (fold / call / raise + сайзинг) и объясняет его.
Все числа считает код, а не LLM.

## Запуск

```bash
pip install -r requirements.txt
python -m poker_coach.ui
```

Консольный вариант:

```bash
python -m poker_coach.cli --hero "Ah Qh" --board "Kh 7h 2c" --pos BB --vpos BTN --line villain_open_hero_call --pot 8.5 --call 3 --stack 94.5
```

Тесты: `python -m pytest`

## Вкладки приложения

- **Игра против ботов** — стол на 2–9 игроков, позиции меняются каждую раздачу. Характеры ботов: стандартный, тайтовый, «телефон», агрессор; можно посадить случайных со скрытыми характерами. Тренер оценивает каждое решение, копит профиль каждого бота и подстраивает советы. Боты по желанию подстраиваются под игрока. Кнопка «Оверлей» открывает компактное окно тренера поверх остальных окон.
- **Разбор ситуации** — выставить любую раздачу один на один вручную и получить совет. В поле «Ставки на постфлопе» можно записать линию торговли (`x b3 c | x b6 c | x b9`), тогда диапазоны восстанавливаются по всей раздаче.
- **Разбор сессии** — загрузить hand history PokerStars и увидеть, где решения разошлись с тренером. Пример: `samples/pokerstars_sample.txt`.
- **Обучение** — учебник из 13 глав: правила, позиции, префлоп, математика, диапазоны, ставки, типы оппонентов, как работает солвер.

## Солвер на Rust

Флоп, тёрн и ривер один на один считает собственный солвер (CFR+) из каталога `solver_rs`. Сборка:

```bash
pip install maturin
```

```bash
cd solver_rs && maturin build --release && pip install target/wheels/solver_rs-*.whl
```

Без него приложение работает: ривер считает медленный солвер на Python, флоп и тёрн — эвристика.

| Улица | Дерево | Время решения |
|---|---|---|
| Ривер | ставки 33% и 75% банка, один рейз | около 0.07 с (на Python — 0.18 с) |
| Тёрн | ставки 33% и 75%, один рейз; на ривере ставка 75% без рейза; все 48 карт ривера | около 1.2 с |
| Флоп | ставка 50%, один рейз; тёрн 66%, ривер 75% без рейзов; по 10 случайных карт тёрна и ривера | около 2.5 с |

Диапазоны на тёрне и ривере берутся из решения прошлых улиц: солвер решает флоп, идёт по сыгранной линии и передаёт веса рук дальше. С этим решение на ривере занимает около 1.7 с (до 3 с).

## Сеть-оценщик

Нейросеть, которая заменяет в солвере нижнюю часть дерева: вместо перебора 48 карт ривера и решения торговли на каждой она сразу выдаёт ценность каждой руки в точке «тёрн закончен». Обученных весов в репозитории нет — сеть нужно обучить у себя.

**Как устроена.** Сеть предсказывает не всю ценность руки, а поправку за торговлю поверх «ценности без ставок», которая считается точно. Каждую руку оценивает общая сеть по семи её признакам (эквити против диапазона оппонента, разброс эквити по картам ривера, доля карт, где рука почти всегда выигрывает и проигрывает, место в своём диапазоне, вес, блокеры) и общему контексту (банк и стек, борд, распределение обоих диапазонов по силе). Признаки считает сам солвер, одинаково при обучении и при игре.

**Порядок работы:**

```bash
python -m poker_coach.valuenet.gen --out data/valuenet/turn --samples 100000 --workers 8
```

```bash
python -m poker_coach.valuenet.train --data data/valuenet/turn --out poker_coach/data/value_turn
```

```bash
python -m poker_coach.valuenet.evaluate --net poker_coach/data/value_turn.npz --data data/valuenet/turn --spots 30
```

- **Данные.** Один пример — случайный борд из четырёх карт, банк, стек и диапазоны; цель считает наш солвер с полным деревом ривера (ставки 33%, 75% и 150% банка, до двух рейзов). Скорость — около 2.2 примера в секунду на 4 ядрах, то есть 100 000 примеров — это около 12 часов на 4 ядрах или 3 часа на 16. Генерацию можно прерывать и продолжать; 100 000 примеров занимают около 0.8 ГБ.
- **Обучение.** На 3000 примеров эпоха идёт 3 секунды на процессоре; на 100 000 примеров видеокарта желательна, но не обязательна. Скрипт сохраняет лучшую по проверочной части версию в `.npz`.
- **Включение.** В `poker_coach/data/params.json` поставить `"value_net": 1`; для замера — `python -m poker_coach.bench --set value_net=1`.

**Что измерено здесь** (обучение на процессоре, 40 эпох; ошибка — средняя по рукам, в процентах банка; без сети, если считать только ценность без ставок, ошибка 10.3%):

| Обучающих примеров | 300 | 700 | 1400 | 2700 |
|---|---|---|---|---|
| Ошибка на проверочной части | 4.48% | 3.66% | 2.96% | 2.45% |

Сквозная проверка сети, обученной на 2700 примерах, на 12 спотах тёрна из PokerBench против точного решения с полным деревом ривера (3.1 с на спот):

| | Время на спот | То же главное действие | Расхождение частоты чека |
|---|---|---|---|
| Сеть, ширина 128 | 1.28 с | у 82% диапазона | 13.6 п.п. |
| Сеть, ширина 64 (`--h 64 --hc 64`) | 0.77 с | у 85% диапазона | не записывал |
| Нынешнее упрощённое дерево ривера | 0.89 с | у 88% диапазона | 8.4 п.п. |

То есть на 2700 примерах сеть ещё уступает упрощённому дереву; ошибка падает примерно на 18% при каждом удвоении данных. Какой она будет на 100 000 примеров и обгонит ли сеть упрощённое дерево, здесь не проверено — это покажет `evaluate` после обучения.

**Ограничения.** Сеть обучается только для точки «после тёрна». Для флопа нужна вторая сеть («после флопа»), генератор для неё не написан. Данные генерируются в основном для стеков 100 bb на начало раздачи (30% примеров — от 20 до 200 bb).

## Проверка солвера

Сверка с открытым солвером `postflop-solver` (`python tools/compare_ref.py`): 40 спотов ривера и 15 спотов тёрна из PokerBench, одинаковые диапазоны с весами и одинаковые деревья без рейзов. Эксплуатируемость — сколько в среднем теряет стратегия против идеального ответа.

У солвера два режима обновления стратегий в CFR+. Медианы по спотам:

| | Ривер, по умолчанию | Ривер, поочерёдный | Тёрн, по умолчанию | Тёрн, поочерёдный |
|---|---|---|---|---|
| Эксплуатируемость на дереве сверки, % банка | 0.11 | 0.01 | 1.56 | 0.19 |
| Эксплуатируемость на боевом дереве, % банка | 0.17 | 0.05 | 2.15 | 0.69 |
| EV диапазона на первом ходе: расхождение с эталоном, % банка | 0.03 | 0.01 | 0.21 | 0.05 |
| EV отдельной руки на первом ходе, % банка | 0.23 | 0.20 | 1.81 | 0.44 |
| Частота чека по диапазону, наш / эталон | 20% / 18% | 17% / 16% | 47% / 46% | 54% / 54% |
| Частота чека по рукам: расхождение, п.п. | 4.7 | 4.1 | 14.3 | 6.7 |

- **По умолчанию** оба игрока обновляются за один проход (300 итераций на ривере, 120 на тёрне, 80 на флопе).
- **Поочерёдный режим** (`RustCFR.alternate = True`): сначала обновляется один игрок, затем другой, уже против его новой стратегии. За то же время эксплуатируемость в несколько раз ниже, и с эталонным солвером он сходится почти точно.
- **Почему по умолчанию не поочерёдный:** с ним совпадение с эталоном PokerBench ниже — 71.8% против 77.5% на тесте и 77.0% против 79.2% на обучающей выборке. Лучше досчитанное решение нашей упрощённой игры (мало размеров ставок, диапазоны-оценки) оказывается дальше от решений, посчитанных на полных деревьях. Причину я не установил.
- На флопе эксплуатируемость измерена на одном споте: около 4% банка по умолчанию и 3.4% в поочерёдном режиме (внутри выборки продолжений борда).
- С PioSolver и GTO Wizard сверки не было.

Флоп решается на выборке продолжений борда (10 карт тёрна × 10 карт ривера из 2352 вариантов). Проверка на 16 спотах против выборки 24 × 24 (в поочерёдном режиме): частота ставки расходится в среднем на 9 п.п., главное действие совпадает в 13 случаях из 16. Выборка 16 × 16 даёт 9 п.п. и 14 из 16 при времени в 2.4 раза больше, равномерная выборка по рангам — не лучше случайной. Оставлено 10 × 10.

## Мультивей

Пороги эвристики для банков на трёх и более игроков проверены симуляцией (`python tools/sim_multiway.py`): 9000 раздач за столом на шестерых против лузовых ботов, из них 602 с мультивей-решением героя; одни и те же раздачи переигрываются с разными порогами.

| Изменение порога | Разница с базой, bb на 100 таких раздач |
|---|---|
| ставить с эквити от 35% (база 55%) | +210 ± 218 |
| от 45% | +100 ± 141 |
| от 50% | +82 ± 110 |
| от 65% | −253 ± 144 |
| рейзить с эквити от 55% или от 75% (база 65%) | +31 ± 69, +10 ± 22 |
| коллировать шире или уже на 5% | −3 ± 92, −12 ± 45 |

Значимо хуже только высокий порог ставки; пороги рейза и колла на результат почти не влияют. Порог ставки сдвинут с 55% до 50%. Проверка сделана против одного состава ботов, склонных коллировать; против тайтовых соперников вывод может быть другим.

## Оценка на PokerBench

```bash
python -m poker_coach.bench
```

Тестовые наборы PokerBench (arXiv:2501.08328): префлоп 1000 спотов, постфлоп — случайная выборка из 10 000 (seed 0).
AA — совпал тип действия, EM — совпал и размер (наш размер приводится к ближайшему доступному в споте).

Выборка 2000 спотов:

| Вариант | Постфлоп AA | Флоп | Тёрн | Ривер |
|---|---|---|---|---|
| A. Эвристика, диапазон только по префлопу | 63.9% | 64.1% | 59.4% | 67.3% |
| B. A + сужение диапазонов по истории ставок | 70.0% | 64.1% | 63.6% | 75.8% |
| C. B + пороги, подобранные на обучающей части (`--no-solver`) | 73.0% | 62.7% | 67.5% | 78.8% |
| D. C + солвер на тёрне и ривере (`--no-flop`, простое дерево тёрна) | 73.2% | 62.7% | 69.5% | 77.6% |
| E. D + солвер флопа, два размера ставки на тёрне | 73.8% | 75.4% | 68.8% | 77.6% |

Выборка 600 спотов (варианты с цепочкой решений считаются долго):

| Вариант | Постфлоп AA | Флоп | Тёрн | Ривер |
|---|---|---|---|---|
| E. Диапазоны по правилам | 71.5% | 68.8% | 68.6% | 74.0% |
| F. E + диапазоны из решения прошлых улиц | 75.3% | 68.8% | 70.6% | 79.6% |
| G. F + солвер и там, где герой уже ставил на этой улице (по умолчанию) | 75.5% | 71.9% | 75.9% | 75.5% |
| H. G + стартовые диапазоны из таблицы солвера и ре-рейз в дереве | 74.8% | 75.0% | 71.8% | 77.1% |

Варианты G и H выбирались на 600 спотах обучающей части (`--train --seed 1`), там результаты такие:

| Вариант на обучающей выборке | Постфлоп AA | Время прогона |
|---|---|---|
| G (по умолчанию) | 77.8% | 872 с |
| G + рейзы на ривере внутри решения тёрна | 77.0% | 1012 с |
| G + ре-рейз в дереве (`max_raises=2`) | 77.5% | 1184 с |
| H: ре-рейз + диапазоны из таблицы (`table_ranges=1`) | 79.0% | 2636 с |

Вариант H выиграл на обучающей выборке 1.2–1.5 п.п., но на тестовой прироста не показал и считается в 2.2 раза дольше, поэтому по умолчанию остался G. Разница между F, G и H на 600 спотах — в пределах шума (около ±1.8 п.п.).

Дальше — два улучшения, которые используют только обучающую часть PokerBench:

| Вариант (600 тестовых спотов) | Постфлоп AA | Флоп | Тёрн | Ривер |
|---|---|---|---|---|
| G. Было | 75.5% | 71.9% | 75.9% | 75.5% |
| I. G + стартовые диапазоны, восстановленные из данных (по умолчанию) | 77.5% | 71.9% | 77.1% | 78.3% |
| J. I + модель поверх выхода солвера (`--calibrate`) | 79.7% | 62.5% | 79.2% | 81.7% |

- **Диапазоны из данных** (`range_data.py`): руки героя в спотах флопа обучающей части — это выборка из диапазона, с которым солвер авторов пришёл на флоп. По частоте рук восстановлены диапазоны с весами для 34 префлоп-линий. На 3000 обучающих спотах вариант I даёт 77.8%, на тесте 77.5% — переобучения нет.
- **Модель поверх солвера** (`calibrate.py`): градиентный бустинг на частотах и EV действий по нашему солверу, обучен на 3000 обучающих спотах (на них 77.8% → 80.6% при проверке по пяти блокам). В основном исправляет споты, где наш солвер коллирует, а эталон рейзит. Она смещена в сторону чека (чеки угадывает в 94% случаев, ставки — в 49%) и подогнана под конкретный эталон, поэтому в приложении выключена.
- **Мягкая точность** для варианта I: в 81.7% спотов мы либо совпали с эталоном, либо его действие по нашему солверу теряет не больше 1% банка (в 85.7% — не больше 3%). В спотах, где солвер уверен, совпадение 80%; где смешивает — 71%. Эталон записывает одно действие даже там, где равновесная стратегия смешанная, поэтому 100% на этой метрике недостижимо.

| Префлоп | AA | EM |
|---|---|---|
| Ручные чарты и упрощённые правила (`--no-table`) | 76.3% | 76.1% |
| Таблица из решений солвера (по умолчанию) | 99.0% | 98.2% |

Оговорки:

- Пороги эвристик (`poker_coach/data/params.json`) подобраны на 2400 спотах обучающей части PokerBench (`python -m poker_coach.tune`); на отложенных 2400 обучающих спотах точность выросла с 69.8% до 73.8%.
- Решения о солвере флопа, дереве тёрна и диапазонах из решения (варианты E и F) принимались по тестовой выборке, так что их цифры слегка оптимистичны. Флоп в выборке мал (142 и 32 спота), его цифры шумные.
- Солвер флопа перебирает не все продолжения борда, а по 10 случайных карт тёрна и ривера: это приближение, от набора карт ответ немного зависит.
- Две настройки дерева солвера («чек в агрессора» и сила диапазона колла) были подобраны на тестовой выборке раньше.
- Префлоп-таблица собрана из обучающей части PokerBench. 795 из 1000 тестовых спотов встречаются в ней с той же линией и рукой; на 144 спотах, где руки в таблице нет и решение берётся по соседним рукам, точность 98.6%.

## Ограничения текущей версии

- Банки на трёх и более игроков считает эвристика, не солвер.
- Деревья солвера упрощены: мало размеров ставок, один рейз, на флопе — выборка продолжений борда.
- За столами на 7–9 игроков таблицы солвера нет: из ранних позиций диапазон UTG стола на шестерых обрезается до типичных для 9-max 10%, 11.5% и 13% рук, против опена из них диапазон продолжения сужается пропорционально. Это оценка.
- Стартовые диапазоны из данных есть для 34 частых префлоп-линий; для остальных — ручные чарты.
- У всех игроков в начале каждой раздачи 100 bb.
- Ходы ботов считаются быстрым способом (диапазоны по правилам), полный расчёт с цепочкой решений — только для совета игроку.
- Разбор сессии понимает только формат PokerStars; скриншоты не поддерживаются.
- LLM не подключена: разбор собирается из шаблонов.
